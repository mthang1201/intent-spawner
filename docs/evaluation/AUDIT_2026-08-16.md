## Corrections

### Runtime and deployment

- Runtime package v2 contains all 16 required files, imports in isolation, and
  is checked against a filename/length/content SHA-256 and package version at
  Hub configuration load.
- `recommender/jupyterhub_integration.py` creates the backend selected by
  `RECOMMENDER_BACKEND`; network backends execute through a bounded async
  executor.
- `/hub/recommendation-preview` returns the locked v2 payload: unified
  recommendation, applied profile, display name, operational metadata, optional
  resource decision, and a one-time preview ID.
- Preview records bind user, TTL, policy, catalog, package, and optional dynamic
  policy generation. They store neither raw intent/code nor raw provider output.
- Spawn requires a form-confirmed preview token. The synchronous callback never
  calls an LLM and never creates an implicit preview.
- Dynamic Mode enriches and revalidates the same record. Re-provisioning issues
  and consumes the same token, explicitly configures `delete_pvc=False`, and
  still rejects any PVC-deleting runtime configuration.
- Operational logs/annotations are restricted to event/backend/version,
  profile/image, fallback category, attempts, latency, and policy identities.
- HTTP endpoints require explicit development opt-in, redirects fail closed,
  API keys are normalized, and responses are capped at 1 MiB.
- `install-proposed.sh` now owns ConfigMap generation, checksum rollout values,
  Secret preflight, backend/auth/mode overlays, and Helm rollout.
  `install-dynamic.sh` is only a Dynamic Mode wrapper.

## Evidence classes and boundaries

- The preserved Protocol-v4 matrices and Stage C records retain their original
  `observed`/evaluation classifications and bytes.
- New mock-service acceptance evidence is **simulated**. It tests operational
  wiring, timeouts, fallback, and privacy; it is not new model-quality evidence.
- No real Gemini request and no authoritative matrix rerun is part of this audit.
- Stage C remains a single disposable-node experiment. Real-user acceptance,
  multi-node generalization, monetary cost, energy, and provider retention are
  not claimed.

## Remaining justified Medium boundaries

1. Preview records are in Hub memory. Restart invalidates them fail-closed; an HA
   production design would require a shared atomic store.
2. Dynamic Mode uses static per-spawn caps and does not reserve or query live
   quota/node headroom. Kubernetes admission remains authoritative.
3. Re-provisioning preserves the PVC but is stop-and-recreate, with kernel state
   loss and no live migration.
4. Plain HTTP is available only behind explicit development/trusted-path opt-in;
   this artifact does not supply service identity or NetworkPolicy for it.
