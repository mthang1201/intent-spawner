\section{Summary of Internship Achievements}
\label{sec:summary_achievements}

This graduation internship project developed and evaluated Intent-Spawner, a context-aware proof-of-concept (PoC) recommender system designed to bridge the gap between high-level user workload requirements and low-level container infrastructure in JupyterHub on Kubernetes. Over the course of the internship, four core objectives were successfully accomplished:

\begin{enumerate}
    \item \textbf{Problem formulation and landscape survey:} We surveyed the operational challenges of interactive notebook environments in multi-tenant Kubernetes clusters. In standard deployments, users face a significant cognitive burden when forced to manually interpret static configuration menus, often leading to misconfigured resources, Out-Of-Memory (OOM) crashes, or severe resource over-provisioning. Conversely, unconstrained language-model-driven configuration risks invalid manifests and policy violations. We formalized this trade-off and established the boundary conditions for an explainable, policy-bounded recommendation workflow that operates strictly over an administrator-approved environment catalog.

    \item \textbf{Design and implementation of the P2 PoC recommender:} We designed and implemented the P2 recommendation engine, which strictly decouples natural language understanding from authoritative cluster infrastructure. The architecture transforms raw user input into an intermediate, schema-validated \texttt{StructuredIntent} object ($I$). Candidate environments are retrieved via a dual-channel hybrid pipeline combining sparse lexical search (BM25) for exact technical terms with dense vector embeddings for semantic context, fused through Reciprocal Rank Fusion (RRF). Infeasible candidates are deterministically pruned by hard constraint evaluation ($F$) against hardware (GPU, CPU, RAM), storage, and architectural policies before applying multi-criteria preference scoring ($c^*$).

    \item \textbf{JupyterHub Pre-spawn lifecycle integration and secure verification:} We integrated the recommendation pipeline directly into the native JupyterHub pre-spawn workflow. To ensure operational transparency and administrative safety, the system presents the recommended candidate for explicit user review. Upon confirmation, the selection is bound to a single-use, time-limited cryptographic verification token. A custom JupyterHub Pre-spawn hook inspects and consumes this token at spawn time, automatically injecting approved resource quotas and digest-pinned container images into the Kubernetes Pod specification without executing runtime inference during scheduling.

    \item \textbf{Empirical feasibility validation via offline benchmarks and capability probes:} We established the practical feasibility of the prototype through focused empirical evaluation streams. Stream~E1 demonstrated competitive offline recommendation accuracy on the development benchmark (\texttt{JointAccept@1} of 65.0\% for P2 Local Mode across 11 paired families) and characterized the performance trade-offs between sparse and hybrid retrieval on domain-specific catalogs. Stream~E5 verified container runtime correctness across 166 recommendation instances, achieving a 100\% pass rate on eligible software probes and confirming up to 44.5\% marginal storage savings through OCI image layer deduplication. Finally, local cluster deployment verified that confirmed recommendations spawn active, responsive Pods on Kubernetes.
\end{enumerate}

\label{sec:thesis_roadmap}

The graduation internship deliverable serves as a proven Proof-of-Concept foundation; the subsequent Graduation Thesis will elevate this prototype into an autonomous, scalable, and rigorously evaluated research system.

The strategic roadmap addresses four complementary facets of the system:
\begin{itemize}
    \item \textbf{Semantic Intent Extractor (Axis 1):} The current prototype relies on lightweight deterministic extraction or basic zero-shot prompting. For the Graduation Thesis, we will incorporate domain-adapted Large Language Models equipped with constrained grammar decoding and structured tool calling. This will enable the extractor to interpret complex, compound workload descriptions (e.g., pipeline stages with conditional GPU requirements or multi-framework dependencies), resolve linguistic ambiguities through interactive multi-turn dialogues, and guarantee 100\% adherence to the formal intent schema.

    \item \textbf{Dynamic Sizing and Reprovisioning (Axis 2):} Static environment allocation at spawn time cannot account for unpredictable runtime data spikes or evolving notebook workloads. We will design an autonomous dynamic right-sizing controller that interfaces with Kubernetes cgroups v2 telemetry. If an active session approaches its memory threshold, the controller can dynamically expand resource limits or seamlessly re-provision the notebook into a higher-tier profile while preserving user state, local filesystem checkpoints, and mounted PersistentVolumeClaims (PVCs) without workflow interruption.

    \item \textbf{Human-Subject Usability Study (Axis 3):} Adhering to academic integrity, the internship project established a comprehensive experimental protocol and testing harness (Stream~E3) without collecting unverified human observations. During the Graduation Thesis, formal user interaction trials will be conducted with recruited cohorts of university students, data science practitioners, and researchers. By comparing Intent-Spawner ($P2$) against standard manual catalog inspection ($B0$), the study will quantitatively measure reductions in configuration time, cognitive workload (via NASA-TLX), and subjective user satisfaction (via standardized SUS metrics).

    \item \textbf{Large-scale Cluster Benchmarking (Axis 4):} The preliminary cluster trials conducted during the internship were confined to a single-node local Kubernetes environment (OrbStack). The Graduation Thesis will deploy Intent-Spawner onto a production-grade, multi-node Kubernetes cluster featuring heterogeneous CPU architectures and dedicated NVIDIA GPU accelerators. Under Stream~E4, we will execute extensive multi-pod stress benchmarks under heavy tenant concurrency to evaluate pod scheduling queue latencies, node packing density, and cluster resource utilization efficiency under real-world multi-tenant operating conditions.
\end{itemize}

In conclusion, this internship report validates the core premise of intent-aware environment selection: by combining structured intent extraction, hybrid retrieval, and hard constraint filtering behind an authoritative pre-spawn lifecycle boundary, user configuration effort can be substantially mitigated without sacrificing administrative governance. The established roadmap provides a clear, actionable trajectory for delivering a comprehensive and impactful Graduation Thesis.
