\section{Conclusion}

The thesis implemented an intent-aware profile and image recommendation workflow for JupyterHub. It extracts structured workload intent, retrieves catalog candidates through sparse and dense channels, applies deterministic hard constraints, and presents the result for user review and confirmation. The administrator-managed catalog and pre-spawn validation keep deployment choices within approved profiles and digest-pinned images.

E1 evaluated recommendation quality on the comprehensive Benchmark v1 test split (471 cases across 157 families with empirical Linux cgroups v2 ground truth). P2 achieved 73.46\% Candidate Accuracy@3 and 81.32\% Profile Accuracy@3 (+47.13\% gain over rule-based P1), while maintaining high execution safety with only 4.67\% under-provisioning. In domain-specific machine learning workloads (PyTorch, TensorFlow, scikit-learn), P2 demonstrated consistent candidate discrimination whereas rule heuristics failed completely (0.0\%). In Stream E2, linguistic robustness evaluation across 471 prompt variants revealed high cross-lingual invariance ($|\Delta| \le 1.28\%$) across Canonical English, Informal/Noisy text, and localized Vietnamese queries.

In Stream E4, kernel resource profiling across 800 physical Pod trials confirmed that calibrated safe envelopes completely avoided out-of-memory terminations under normal operating envelopes. Furthermore, a 50-node cluster simulation driven by empirical Alibaba PAI GPU workload traces demonstrated that P2 eliminated pending admission queues (reducing peak queue wait from 21.30 minutes down to zero) and prevented GPU monopolization, unlocking a 5.2x theoretical multi-tenancy multiplier. In Stream E5, all 76 eligible container functional probes passed successfully, and OCI image manifest analysis verified a 27.61\% compressed layer deduplication rate across approved images.

\section{Future work}

The experimental results are subject to several limitations. The evaluation is based on a controlled resource and image catalog and therefore does not cover the full diversity of workloads, arbitrary bare-metal Kubernetes clusters, and bespoke software stacks. Future work can extend the evaluation to larger and more heterogeneous catalogs, additional specialized workload domains, and interactive human usability studies with live user cohorts. Historical workload telemetry could also be incorporated into continuous feedback loops to dynamically tune resource envelopes based on previously observed runtime behavior. Language-model-based re-ranking could also be explored as an optional refinement stage, provided that its latency overhead and accuracy benefits are systematically evaluated against tight real-time budget requirements.
