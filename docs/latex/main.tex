\addcontentsline{toc}{chapter}{Abstract}
\begin{preamble}{Abstract}
Shared JupyterHub deployments commonly expose administrator-defined notebook environments through manual profile and image selectors. This preserves operational control, but requires users to translate a workload described in semantic terms into software-image and Kubernetes resource choices before a pod exists. This thesis studies Intent-Spawner, a bounded pre-spawn decision-support workflow for that choice. Its principal method, P2, converts natural-language workload intent and explicit hints into a validated structured representation, retrieves administrator-curated candidates using BM25 and dense retrieval, fuses their ranks with Reciprocal Rank Fusion, removes candidates that violate hard constraints, and ranks feasible candidates deterministically. The selected identifier is resolved from trusted administrator data and checked against policy, profile allowlists, catalog versions, and digest-pinned image identity. A preview lets the authenticated user confirm, edit, or choose an allowlisted manual override. A single-use, user-bound token binds the confirmed preview to the pre-spawn hook, which applies the stored decision without recomputing the recommendation.

The thesis defines B0 as ordinary manual JupyterHub selection, P1 as a frozen rule-based recommender, P2 as the proposed structured-intent hybrid-retrieval method, and P3 as an optional grounded language-model reranker. Protocol-v5 separates offline recommendation and language robustness (E1/E2), human outcomes (E3), independently observed resource envelopes (E4), and image functionality and storage (E5). P3 was not retained after its development gate. Available evidence includes a development-only E1/E2 run over 18 workload families and 83 prompt variants, local OrbStack E4 observations of 421 Pod trials across 20 workload families, and E5 Docker/OCI observations for four digest-pinned images on linux/arm64. These packages are bounded observations, not confirmatory evaluations. E3 has no participant observations; the consolidated Protocol-v5 analysis is INCOMPLETE and all confirmatory decisions are \texttt{NOT\_EXECUTED}. The thesis therefore presents the system design, implementation, and evaluation infrastructure, but does not claim confirmatory superiority, user benefit, general cluster efficiency, production readiness, or realized node-storage savings.

The main contribution is an auditable composition of workload-intent parsing, hybrid retrieval, deterministic feasibility and ranking, trusted catalog resolution, and explicit human confirmation at the JupyterHub pre-spawn boundary. The work also establishes a reproducible protocol for evaluating recommendation quality, language robustness, human outcomes, resource envelopes, and image behavior as distinct constructs. Optional dynamic sizing and stop/recreate reprovisioning are prototype extensions; neither is an exact demand oracle nor live migration.

\textbf{Keywords:} JupyterHub; Kubernetes; workload intent; hybrid retrieval.
\end{preamble}
